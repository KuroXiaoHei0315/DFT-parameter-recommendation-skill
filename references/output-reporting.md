# 输出报告规范

用户要的是“看懂结果”，不是先读日志。文献下载任务的输出应按这个顺序交付。

## 第一优先级：下载报告

优先给：

- `下载报告.pdf`
- 如果没有 PDF，则给 `下载报告.html`

报告开头必须有 5 个数字：

- 找到/尝试的文献数。
- 已下载 PDF 数。
- 已保存 HTML/XML 全文数。
- 未能直接合法下载数。
- 需要用户下一步处理数。
- 已核验影响因子/分区数。

## 第二优先级：实际文件

告诉用户实际文献在哪里，例如：

```text
<下载目录>\<主题名>\
```

文件名要能看懂：序号、年份、短题名，避免 `main.pdf`、`download.pdf`。

## 第三优先级：下一步清单

对没下成的文献，不只写 `403`，要翻译成人话：

- `http_403`：平台拒绝直连，通常需要学校图书馆、机构 VPN 或浏览器人工访问。
- `paywall_or_login_detected`：遇到登录/订阅页面，不能自动下载。
- `no_candidate_url`：没有找到可尝试的全文链接。
- `HTTPError`：入口可能变了，需要人工复查。

## 影响因子显示

报告应显示“影响因子/分区”列，但不要凭空生成指标。

优先级：

1. 用户或 agent 已核验的 `candidate_table.csv` 字段。
2. `journal_metrics.csv` 中的期刊指标。
3. 无指标时显示“待核验”。

推荐字段：

```text
journal,impact_factor,jcr_quartile,metric_year,metric_source,indexing,venue_note
```

写法示例：

```text
IF 11.3；Q1；SCIE; Scopus；2024 / JCR
```

如果没有 JCR 权限，可以使用 SJR、CiteScore 或出版社页面，但必须标清楚 `metric_source`，不要把不同指标混称为影响因子。

所有列出文献的表都必须直接包含这些列：

```text
题名,年份,期刊或来源,影响因子,JCR分区,指标年份,指标来源,索引情况,DOI,文章地址,全文状态,下一步建议
```

`期刊指标.csv` 只能作为后台核验模板或数据源，不要作为主要交付物。用户不应该为了看一篇文献的期刊质量，再去另一个表里查。

## 第四优先级：CSV 证据链

CSV 放在最后说明：

- `总下载日志.csv`：最终状态总表。
- `下载日志.csv`：下载尝试日志。
- `补充下载日志.csv`：补下载日志。
- `候选文献总表.csv`：候选文献表。
- 英文文件名可以保留为脚本兼容备份，但不要作为用户主入口。

不要把 CSV 当作主要交付物。

## 文件命名

除实际文献 PDF/HTML/XML 外，所有交付文件优先用中文名：

```text
README_先看我.md
00_先看我_文件说明.txt
下载报告.pdf
下载报告.html
文章地址总表.csv
检索计划.md
配置文件.json
候选文献总表.csv
高优先级文献.csv
中优先级文献.csv
低优先级文献.csv
下载日志.csv
总下载日志.csv
去重清单.csv
已下载全文/
内部数据_一般不用打开/
```

实际文献文件名保留“序号_年份_短题名”，因为论文题名通常是英文，这样更方便引用和去重。

根目录不要同时堆满英文和中文文件。英文兼容文件、原始日志、中间目录放进 `内部数据_一般不用打开/`。根目录只保留普通用户会打开的中文交付物。

## 推荐用户回复

```text
我已经下载并生成报告：

- 下载报告：<下载目录>\...\下载报告.pdf
- 实际文件：<下载目录>\...
- 成功 PDF：13 篇
- 网页全文：1 篇
- 未能直接合法下载：6 篇
- 已标注影响因子/分区：12 篇

没下成的主要原因是出版社限制直连下载，不是程序失败。下一步建议用学校图书馆/VPN、馆际互借或联系作者。
```
